# Cleanup pass, 2026-11-06: handoff

This was a code cleanup across the gameplay-engine-v2 product path. It covers `df-table`,
`df-table-host`, `df-playground` and `df-scene-layout`, and the host's dependency crates `df-api`,
`df-protocol`, `df-types`, `df-observe`, `df-telemetry`, `df-rules`, `df-ai`, `df-providers` and
`df-imagery`. The rules to follow from now on are in
[planning/coding-style.md](../planning/coding-style.md), section 6, "Interface shape (one
convention per concern)".

## What changed

- **One surface per service.**
  - Text generation goes through the durable text service, on the Codex or Responses backend.
  - The scene-layout contract is one crate (`df-scene-layout`), shared by the page, the host and the
    CLI.
  - Host plumbing has one of each: atomic file write, route reply envelope (`dev_http::DevReply`,
    tagged `outcome`), body parser, dev CLI client (`dev_client`) and environment reader. Audit lines
    are echoed once, in the request middleware, and the host's event log is the df-observe audit
    sink.
- **One patch type for live scene changes.** `overlay::Edit<T>` (`Keep`/`Clear`/`Set`) replaced
  `Override`, `CaptionOverride`, `ScreenOverlay` and bare `Option`s. Coverage tests in
  `scene_slots_tests.rs` stop compiling when a scene field is added without being classified.
- **Typed errors and names.**
  - Errors are named `*Error` and carry a typed `cause`. They implement `Display` and
    `std::error::Error`, and HTTP-facing errors have `status() -> StatusCode`.
  - In df-table, `*Fault`/`*Refusal` became `*Cause`/`*Error`.
  - In df-playground, `Bad*` became `Invalid*`.
- **Layout.**
  - Modules follow the `feature.rs` + `feature/child.rs` layout, with no `#[path]` and no prefix
    families (`view/`, `home/`, `lobby/` in the playground).
  - Tests are in `<module>_tests.rs`.
  - Limits are in one `limits.rs` each.
- **Narrower surface.** 70 df-table items that nothing outside the crate used are now
  crate-private.
- **Limits for dev work.** Bounds that only guard against mistakes are generous and named with
  units: 1 h request timeout, 256 MiB bodies, 1 GiB asset files. Bounds tied to external contracts
  say so: the RPC 64 KiB message, database CHECKs and provider limits.
- **Testing studio.** The playground page's chrome was redone:
  - grouped toolbar
  - distinct looks for choices, switches and actions
  - scenario titles
  - fold-out notes strip
  - TV-first layout
  - Nothing drawn inside the TV or phone changed. SAM stays on by default, and there are no speech
    bubbles.
- **Real bugs fixed, about 30, each with a test.**
  - Music longer than about 8.7 min could never be received after it was billed.
  - World Labs: an address filter gap, credit rounding, and PUT sent as POST.
  - Overflow panics in SAM mask, layout and rules arithmetic.
  - Two rules test files never compiled.
  - Imagery: memory budget checked too late, partial usage booked as zeros, and misreported
    work-folder failures.
  - Telemetry fixtures hard-coded to another machine.
  - Host: audit-line injection, layout lost-update races, live-backdrop mismatches, broker limits
    that silently stopped work, unbounded job list, and unaudited refusals.
  - Playground: stale pill and panel redraws, and a notes strip that kept "Live changes" after a
    reset.

## Wave 3 (commit 7003ce99)

- **Typed CLI refusals.** `DevError::Rejected(String)` is gone, so the CLI and tests match typed
  route errors. Playground and media refusals still carry `cause: None` until
  `wire::Reply::Rejected` is typed.
- **Status codes.** `client::Response.status` is a `StatusCode`.
- **`key()`/`from_key()`.** These, with drift tests, replace `label()`/`parse()` in df-ai,
  df-telemetry, df-providers, df-observe, df-imagery and df-rules.
- **Error types.** Errors have `Display` and `std::error::Error`, and are named
  `*Error`/`*Cause`.
- **Audit lines.** df-observe counts audit lines that have no sink instead of printing them.
- **Runtimes.** The nested runtimes in df-imagery are removed.
- **Rules wire names.** df-rules wire names are snake_case, and old spellings are still read through
  aliases.
- **Scene layouts.** df-scene-layout reads layouts only through checked records.

## Persona (commit 873f215f; design in planning/chat-pipeline.md)

A persona is the authored description of a character: `df_content::persona` (identity, job,
personality, speech style, public backstory; the character's own drives, private backstory,
boundaries, secrets, behaviors and triggers), with typed edits, a pure persona-generation question
and an additive-only backfill steered by optional narrative guidance. The host stores personas under
`assets/playground/personas/` and exposes them through the dev API and CLI. Defaults use the
`gpt-6-luna` model; every call can override the model.

Decisions and open points an owner or coordinator should settle:
- **A model inventing lasting detail** (generation, backfill) conflicts with
  `planning/interaction-engine.md` ("never invents persistent personality") and
  `planning/narrative-engine.md` (invented claims cannot become canon). It is a development tool by
  the owner's decision; in production the interaction and narrative engines own what becomes canon.
  `Strict` latitude is the cautious setting.
- **`NarrativeGuidance`** (arc, phase, beat, hooks, threads, must_establish, must_avoid, tone,
  latitude) restates concepts that exist as `df_model` records (`StoryArc`, `CharacterHook`) as free
  strings, and no planning document names it. Replace it with the real narrative-engine types when
  that engine is wired in.
- **Crate placement.** The two question modules (`persona::generation`, `persona::backfill`) build
  prompts and JSON schemas in `df-content`, which `planning/c-df-content-d01-decision.md` keeps to
  records and pure validation. The precedent is `df_imagery::identity_question`. Consider moving them
  to `df-ai` or the host.
- **Persona id grammar** duplicates `df_scene_layout::is_character_name`; a drift test in `df-content`
  pins them together (dev-dependency), so a change to either fails the build.
- **A persona file in a newer schema** reads as an unknown-field error, not "unsupported schema",
  because the schema check runs after `deny_unknown_fields` (the layout reader works around this
  with a separate schema read).
- `crates/df-content/tests/import.rs` has an unrelated clippy fix (`assert_eq!(.., &[])` to
  `is_empty()`).
