## One record owner and pipeline

TextService/AudioService own their lifecycle facts; features own semantic verdicts, session owns approved delivery and devices own playback/capture observations. Each submits a typed GenerationEvent to df-observe. The proposed `GenerationLogV1` envelope maps to one OTEL LogRecord; optional spans/metrics and existing readable audit/timeline/console representations derive from that same logical record. The handling boundary records a failure once; propagation records a reference or distinct outcome, not another counted failure. Do not parse free-text audit lines to reconstruct the new contract.

Pipeline: owner -> df-observe typed admission/redaction -> existing native/browser bounded transport -> df-telemetry ingress/spool/SQLite -> authorized read-only reader. No new log store, ledger, console collector, separate audio/text logging pipeline or message-broker infrastructure. Neutral envelope/field types stay in df-observe; df-ai/df-media/imagery/finance map their own domain facts into them. Never add reverse dependencies from df-observe to those consumers. Keep emergency exporter diagnostics as the existing bounded independent fallback, not recursive OTEL emission.

Emit a LogRecord independently of sampled spans or presence of a trace SDK. `OperationSpan::event` alone cannot satisfy log capture. Preserve readable audit consumers with a compatibility rendering of the same record ID; do not feed that rendering back into a second log record. Use existing finish_audit_record-style recursion suppression while replacing the bridge. Metrics increment once from the owned semantic transition; duplicate export/receipt/replay cannot increment again. Trace span events may reference the logical log ID, but queries count the LogRecord, not both representations. Each exported span has its own physical CaptureKey/record_id/source_sequence from the same producer allocator; it must never reuse the log CaptureKey for a different span payload. A logical causal reference is not transport-record identity.

## Envelope and causal identity

Schema name `df.generation/1`, instrumentation scope/version and event vocabulary version travel with every record. Compatible additions use optional typed fields; changing meaning/units requires a version. Unknown versions remain visibly unsupported, not coerced. These names are proposed contract fields, not existing wire/SQL columns.

| Required field group | Semantics |
| --- | --- |
| Record | event_name, event_version, severity, outcome/reason enums; producer_id + producer_boot_id + strictly increasing source_sequence + stable record_id. Bind boot identity to the existing ProducerId lifetime rather than a second sequence allocator. Reserve ID/sequence before admission; failed admission leaves an explicit possible gap. |
| Time | OTEL Timestamp = source event wall time when known; ObservedTimestamp = collection observation, never silently substituted for source time. Also monotonic_elapsed_ns, duration_ns with named start/end stages, clock_domain and measurement_state. Unknown time/duration is null + reason, never zero. |
| Source | service/instance/build, config revision, mode, operation_class and safe purpose/profile/backend/model references; source, prompt/template/schema/validator/locale revisions as applicable. Resolve arbitrary model/profile names through authorized config lookup; do not copy secret-like operator strings into logs. |
| Authority basis | Scope-controlled opaque tenant/campaign/session/run references, recovery_epoch and generation when applicable, audience/projection/rights revision and owner binding. Non-game jobs use their actual authorized scope, not fabricated session IDs. Correlation metadata never authenticates or authorizes. |
| Work links | request_id, operation_id, job_id; conditional stage_id, attempt_id, parent_job/stage/attempt, candidate_id and qualification_revision, stream_id, capture_id, cue_id, asset_id and delivery_id. Record absence/not-applicable explicitly. A candidate or asset ID is opaque, not a raw content hash. |
| Causality | Optional trace_id/span_id/flags, causal record/operation links, coalesced_job link and outcome_revision/transition identity. Record identity dedupes transport retry; transition identity distinguishes replayed observations from a newly executed provider attempt. |

Capture this immutable context before spawning, queueing, subprocess launch or provider egress. Child completion uses the captured build/config/run/basis even after reset; current owner may separately reject it as stale. Each shared job/attempt has one lifecycle; coalesced waiters have separate linked request/delivery records and cancellation interest. Do not charge or duplicate provider spans per waiter. Durable jobs retain minimal causal IDs for restart; new process gets a new producer boot, while recovered attempt keeps its original identity and a recovery link. Old event transport retries retain exact ID/sequence/bytes; changed bytes under that identity are a conflict.

Measure durations with a monotonic clock inside one clock domain. Wall timestamps may jump; clocks on browser/server/provider can differ. Order by explicit causal edges and per-producer sequence, not wall-time sort alone. Never subtract browser performance.now from server Instant or label provider timestamps as measured server latency. Cross-device end-to-end estimates carry offset/RTT uncertainty or are Unmeasured; queue, supplier, decode and playback-local durations remain separate. Audio frame offsets/sample rate and AudioContext anchor are distinct from telemetry timestamps; identify suspension/reanchor epochs.

## Versioned event vocabulary and emission ownership

All names below are prefixed `generation.`; v1 freezes enum payload schemas in T0/A0. Common envelope is required for every row. Additional fields are mandatory when that operation exists. INFO is the operational default, WARN is a handled degradation/uncertainty, ERROR is failed owned work or violated invariant; normal cancellation/refusal is not automatically ERROR. Closed reason/outcome codes carry causes, never vendor prose.

| --- | --- | --- |

| dispatch, provider_result, recovery, terminal | Service attempt owner / INFO; WARN Unknown; ERROR failed work | attempt and stage, send_state (Unsent/PossiblySent/KnownSent), supplier operation reference, elapsed/bytes/counts/format facts, failure_class, terminal/Unknown/recovery disposition. | music_child, transform | AudioService recipe/stage owner / INFO; WARN optional failure; ERROR required failure | parent/set/band revision, required/optional role, bed/motif/tension/combat/ambience child ID, duration/loop/frame/format measurements, ordered transform revision, output asset, codec capability/failure. INFO records transitions and terminal summaries, not every token, sample, partial hypothesis or audio chunk. Aggregate high-frequency transcript/buffer/clock changes in configurable monotonic windows (starting default 1 second) and flush counts/min/max at stream end; this is defined instrumentation granularity, not sampling emitted logs. Optional metadata-only chunk TRACE records sequence/frame/byte/latency facts under an operator-selected stream/job scope and expiry; never content. Every such emitted enabled record remains subject to full capture. No suppression disguised as "metrics only" for required terminal, Unknown, failure or gap events.

Logs preserve searchable transition facts; traces add parent/linked spans and duration structure; metrics show bounded counters/histograms/gauges. Metric labels use only finite operation class, service/backend family, event/outcome/failure enum and delivery/format class. No request/job/attempt/candidate/tenant/player/voice/asset/trace IDs, arbitrary model/profile/purpose strings or hashed content as metric labels. Configure finite label sets/overflow category explicitly; preserve unrecognized values in authorized logs through safe references.

## Privacy, costs and developer controls

Routine INFO/DEBUG/TRACE excludes prompts, model output, player words, transcripts, raw audio/images, credentials, headers, signed URLs, arbitrary filesystem paths, provider error bodies and stderr. Typed approved fields are selected before formatting/export; Debug/Display and panic/error formatting obey the same policy. Safe opaque references are scoped and access-controlled; plain content hashes are not presumed safe. Avoid raw voice names or client-provided trace metadata in exception strings.

DEBUG/TRACE does not authorize payload capture. If existing authorized diagnostic evidence policy permits a payload specimen, store it only in that policy's scoped access-controlled evidence destination with explicit content class, expiry/retention, redaction and deletion handling; routine log carries only its opaque evidence reference. No new consent flow or payload archive is introduced. Default STT remains ephemeral; a telemetry/recovery journal never saves waveform/transcript merely to improve diagnostics. Synthetic fixture payloads can be fully inspected directly in fixtures/evidence without production secrets, credentials or a real account.

Cost events reference the existing local SpendLedger/MeteringPort or hosted finance authority. Exact token/character/audio-frame/duration/credit/subscription quantities keep units and reported/measured/estimated/bill-confirmed evidence separate; rates/currency/rounding pinned to the booked revision. Unknown/unpriced/zero new source-generation cost on reuse are distinct; a reused candidate may still need a separately metered critic/revalidation, so the total request is not presumed free. Child text judgments, four-plus-one music attempts, rejected/cancelled-after-send work and transformations retain lineage; rollups count underlying supplier attempts once. Logs cannot reserve, settle, release liability or reconstruct missing authoritative money state.

Expose file/environment/launch/authorized-runtime logging profiles with severity/category, scope and expiry for detailed trace/chunk events, redacted effective provenance and atomic reload/restart reporting. No rebuild or arbitrary model/path/test-count whitelist. Changing one generation profile's logging never silently changes model, output, execution mode or content retention. Global generation disable, device mute and logging disable are separate. Logging level/category/detail/off settings and exporter failure add no new TextService/AudioService generation refusal; only existing expressly configured service readiness policy may affect admissions, independently of the mandatory financial journal. Admit finite configurable queue/record/batch/byte/window/flush/deadline/retention bounds, including larger finite development envelopes; actual protocol/host constraints return typed diagnostics.

A logging configuration change is recorded by the independently enabled control/health category when available; disabling that category/all telemetry is visible through authorized config/health reads. Off means no capture at that level/category, not a successful empty corpus. Record the effective selection for a review interval; do not claim missing events were captured when logging was disabled. Operator diagnostic scope expiry restores the prior profile atomically.

## Capture, loss and storage truth

Capture all emitted records at enabled levels without log sampling, independently of trace sampling. That is a capture requirement within finite admitted resources, not a promise of losslessness through disk failure or process death before durable spool. Producer reserves identity before bounded nonblocking encoding/admission; queued/Pending is Unconfirmed until a matched Spooled/Committed receipt. Exact retry bytes and IDs permit dedupe; receipt loss does not invent a new record. Sequence gaps are visible, including tail uncertainty where exact lost range is unknowable.

df-telemetry owns disk work, spool retry/drain/checkpoints and SQLite. Expose producer last-reserved/last-confirmed, ingress admitted/refused, spooled/committed watermarks, duplicate/conflict counts, backlog age/bytes, retention start/evicted ranges and missing source/client ranges. A page closing before upload has a best-effort tail, not native durability. Absent playback reports mean Unobserved/Unknown, not successful silence or completed speech. Legacy line truncation and ring eviction require explicit counts/fields, not silent apparent completeness.

On queue/spool/disk/SQLite exhaustion, bounded admission fails fast; emit a safe gap/health outcome through surviving shared health/emergency facilities, keep in-memory counters and expose uncertainty on subsequent recovery/read. If disk and stderr both fail, exact evidence may be unrecoverable: surface the degraded interval and last known watermark, never fabricate ranges or completeness. Do not block gameplay input/render/provider callbacks indefinitely. Follow existing service readiness policy for sustained telemetry degradation/new high-volume admissions; already-admitted gameplay reaches its safe checkpoint.

Mandatory financial/effect intent/possible-send/recovery journal is separate and still gates paid dispatch under Service operations. Telemetry failure alone is not permission to omit that journal, and telemetry success is not its durability receipt. No payment/gameplay state is recovered by replaying logs. Finite retention/rotation obey current access/deletion and service quotas; pinned evidence consumes its existing reserved capacity, with explicit health if unavailable.

## Implementation and acceptance gates

T0/A0 freeze the envelope, event/schema versions, per-event owner/required-field validation, privacy types, config activation and compatibility bridge with df-observe/df-telemetry owners. T1/A1 wire one offline end-to-end producer/ingress/reader path before new backends; T2-T5/A2-A5 migrate the listed source anchors and remove duplicate/parsed generation logs. T6/A6 require the following observed fixtures on the submitted implementation; this documentation task ran none:

- Trace unsampled/no SDK: every enabled required lifecycle log remains queryable; logging disabled is visibly disabled. Audit rendering and trace links never double-count a logical outcome or metric.
- Concurrent tasks/waiters/reset: captured context cannot bleed across async polls; old completion keeps original basis; coalesced requests link one attempt; no audit_scope held across await.
- Retry/restart: identical record ID/bytes dedupes, changed bytes conflicts, boot/sequence never reused; recovered attempt/cost identities remain stable and late corrections append revisioned observations.
- Outage/disk full/crash before and after receipts/spool/commit/checkpoint: bounded responsiveness, explicit refusal/gaps/emergency/last watermarks, recovery drain without duplicate records; no finite-buffer lossless claim. Financial journal failure still prevents paid dispatch.
- Redaction sentinels in prompts/output/STT/audio/ref names/headers/URLs/stderr/provider errors/Debug never reach logs/traces/metrics/exports; authorized synthetic fixtures remain inspectable. No plain private-content hash leakage.
- Text candidate structural vs semantic/correction/delivery linkage; audio capture partial/final/cancel, four-plus-one music child failure, transformations, decode/underrun/mute/reanchor/route/stale events and missing client reports are classified without content or false audibility.
- Config reload/rollback/expiry and finite-envelope increases without rebuild; category-level/detail scope and disabled intervals visible. Metrics cardinality stays within declared finite label sets; ledger parent/child rollups count one supplier charge each.
- Read-only bounded query/export preserves typed attributes, source/observed clocks, causal links, retention/loss/watermarks and authority boundaries. Browser/audio runtime acceptance remains a separate future gate.
