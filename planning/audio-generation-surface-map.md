## Bypass removal and guard coverage

The guard must classify operation semantics rather than ban all HTTP, process execution or backend names. Audio providers become private; feature code cannot invoke registered_speech_provider, NativeSpeechProvider, NativeElevenMusicProvider or submit_sound after cutover. Shared Fal video/image transport remains legal for its owner; sound dispatch does not.

Extend existing call-site/cost/imagery boundary tooling with audio ownership checks, Cargo dependency checks, AST/call-site analysis of HTTP/SDK/process/factory paths and script scans. Seed a forbidden direct audio-call fixture to prove detection; record unexpected runtime fake-transport dispatch without job/attempt/money identity as an integration failure. Ordinary model/profile/endpoint/voice/options/finite limits and fixture changes remain unrestricted within typed capabilities and current policy. No permanent "developer tool" or test exemption that grants production callers raw execution handles.

Acceptance mapping is A0-A6 and the boundary matrix in the companion architecture. Each R row must acquire a same-API fixture/integration check and downstream consumer evidence; A/C/P rows must stay honestly classified or gain explicit integration before capability claims. No number of isolated helper tests proves audible output.
